# Scene Editor 3: 3D Asset Import/Export Implementation Plan

> Status: implemented; security reviews returned changes (see README *Known gaps*).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement 3D model import/export for the workplace editor: upload and validate `.glb` / self-contained `.gltf` assets, store models in a local server library, render normalized `model` items in the 3D scene, provide a model library manager, export standalone `.glb` scenes, and import/export portable `.ruang-bundle` JSON archives.

**Architecture:** A server-side model store in `server/models.ts` mirrors `server/skin-library.ts` with atomic writes, strict glTF/GLB binary validation, and size/count caps. `src/scene3d/scene.ts` and `server/scene.ts` add `ModelItem` under `kind: 'model'` and bump `ScenePatch` to version 2 (with backwards compatibility for v1). Three.js `GLTFLoader` renders normalized models within 1.5-unit bounding boxes. `GLTFExporter` handles scene `.glb` downloads via lazy dynamic import. Portable `.ruang-bundle` files pack `added` items and base64 models with collision remapping on import.

**Tech Stack:** React 19, React Three Fiber 9, three 0.186 (`GLTFLoader`, `GLTFExporter`), Express, vitest, TypeScript strict.

**Spec:** `docs/superpowers/specs/2026-10-14-asset-io-design.md` (binding). Predecessors: `docs/superpowers/specs/2026-10-10-scene-editor-structure-design.md`, `docs/superpowers/specs/2026-10-10-scene-as-data-design.md`.

## Global Constraints & Contracts

- **Server Security & Boundary**:
  - Model directory: `$RUANG_DATA_DIR/models/` (fallback `~/.local/share/ruang/models/`). Mode 0700 for directory, 0600 for files. Atomic writes via tempfile + rename.
  - Model ID format: `/^m-[0-9a-f]{12}$/` (random hex generated on server).
  - Model naming: sanitize to `[A-Za-z0-9 ._-]`, max 64 characters, fallback `'model'`.
  - Caps: max 100 models, default 10 MiB (`RUANG_MODEL_MAX_BYTES = 10485760`) per model.
  - Validation: reject non-v2 (`asset.version !== '2.0'`), reject Draco/KTX2/basisu extensions (`KHR_draco_mesh_compression`, `KHR_texture_basisu`), reject external URIs (buffers/images must have no URI or inline `data:`).
- **Scene Schema**:
  - `ModelItem`: `{ id, kind: 'model', level: number, modelId: string, position: [x,y,z], rotation?: number, scale?: number, view?: 'cutaway'|'shell'|'both' }`.
  - `ScenePatch`: bump version to 2. Server accepts v1 and v2, saves v2. Client `EMPTY_PATCH` uses version 2.
- **Normalization**:
  - Largest dimension normalized to `1.5 * (scale ?? 1.0)` world units. Centered on X/Z, min-Y placed at `position[1]`.
- **Bundle Format**:
  - Max 40 MiB bundle size, max 20 models. Format `ruang-bundle`, version 1.
- **UI Rules**:
  - Flat styling using `styles.css` tokens, no floating cards or heavy shadows, responsive to ~480px, light/dark mode support.
- **Card Chain**:
  `spec -> (server store || scene schema+renderer) -> palette import UI -> library UI -> export (single+scene glb) -> bundle -> README/API_VERSION -> Opus reviews`.

## Identified Risks & Mitigations

1. **Hostile GLB/glTF Input (Buffer Overrun / DoS / Resource Leaks)**:
   - *Risk*: Malicious files with malformed binary headers, huge declared chunk lengths, circular JSON structures, or external network requests (`http://...`).
   - *Mitigation*: Parse headers using strict byte length checks. Verify magic `0x46546C67` and version `2`. Reject any URI not starting with `data:`. Strip/reject unknown or compressed extension declarations before passing to loaders.
2. **Memory Exhaustion on Large Base64 Bundles**:
   - *Risk*: A 40 MiB bundle containing 20 base64-encoded models can inflate browser memory usage by 4x-5x during JSON serialization, causing tab crashes on constrained devices.
   - *Mitigation*: Enforce hard client-side limits (40 MiB, 20 models). Validate file size before parsing. Decode base64 payloads sequentially during import rather than all at once.
3. **GLTFExporter Failures on Procedural Scene Props**:
   - *Risk*: Procedural materials (canvas textures from `textures.ts`, custom shaders, non-standard R3F nodes) may fail serialization or drop textures during `GLTFExporter.parse()`.
   - *Mitigation*: Clone the scene graph, convert procedural canvas textures to standard data textures/canvas snapshots, strip non-mesh editor objects (gizmos, selection wireframes, helper lights), and test GLTFExporter against the stock default scene.

  - Implement `validateGltfBytes(bytes: Buffer): { format: 'glb' | 'gltf', name?: string }`:
    - GLB: Check magic `0x46546C67`, version `2`. Extract JSON chunk 0.

  - `POST /api/models?name=...`: raw byte upload with content-type checking.
  - `GET /api/models/:id/file`: stream original file with `nosniff` and `Content-Disposition`.
  - `DELETE /api/models/:id`: delete model if not used in `scene.json` (return 409 with `usedBy` if referenced).
